pakka  ·  how it works

A staging layer between the agent and its systems

Tom's agent is Pydantic AI. The layer is a Modal service. Every decision is a Logfire span.

browser   web/app.js

   ▼
Modal app  pakka/app.py
   FastAPI · min_containers=1 · modal.Dict

record  Logfire: agent tool-call spans with
        pakka.write / pakka.decision nested under them

Pydantic — tool arguments are models, so editing a held write is model_validate against the tool's own schema. The envelope builder walks model_fields and keys on types. It never reads a field name.

Pydantic AI — one agent class, any model, by changing one string. Transcripts recorded once, replayed through a FunctionModel; the layer decides live on every call.

Modal — the layer is a service with a public URL. Each Friday is a function call. State in a modal.Dict.

Logfire — the PR timeline and the Insights tab, for an agent. Written to, never read from.

Pydantic AI Gateway — a gateway rule makes any agent behave behind the layer without touching its code. The gateway governs what the agent thinks with; pakka governs what it does.
